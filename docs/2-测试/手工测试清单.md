# 手工测试清单

自动测试(`npm run verify`)覆盖加密、保存、导入导出、限速等纯逻辑;**本机服务和页面**需要下面的手工检查。每次发布前照着走一遍,打勾。

准备:用临时目录,不要碰真实保险库。

```bash
npm start -- --no-open --port 8777 --config /tmp/vp/config.json --vault /tmp/vp/test.enc
```

控制台会打印 `http://127.0.0.1:8777/login?t=…`。

## A. 本机服务与登录(用 curl)

把下面的 `LINK` 换成控制台里的登录链接。

| # | 操作 | 期望 |
|---|---|---|
| A1 | `curl -i http://127.0.0.1:8777/` | 401,提示未登录 |
| A2 | `curl -i http://127.0.0.1:8777/api/status` | 401 |
| A3 | `curl -i -H "Host: evil.example:8777" http://127.0.0.1:8777/` | 403 `forbidden host` |
| A4 | `curl -i -c jar.txt LINK` | 200,页面含 `<meta http-equiv="refresh" content="0;url=/">`,`Set-Cookie` 含 `HttpOnly; SameSite=Strict` |
| A5 | 再用同一个 LINK 请求一次 | 403(链接只能用一次) |
| A6 | `curl -i -b jar.txt http://127.0.0.1:8777/api/status` | 200,`unlocked:false` |
| A7 | `curl -i -b jar.txt -H "Origin: http://evil.example" http://127.0.0.1:8777/api/status` | 403 `forbidden origin` |
| A8 | `curl -i -b jar.txt -H "Sec-Fetch-Site: cross-site" http://127.0.0.1:8777/api/status` | 403 |
| A9 | `curl -i -b jar.txt http://127.0.0.1:8777/api/entries` | 423(已锁定) |
| A10 | `curl -i -b jar.txt -X POST --data-binary @/dev/zero --max-time 3 http://127.0.0.1:8777/api/unlock` | 返回 413 并关闭连接,进程不崩溃、内存不增长(上限 64 KB) |
| A11 | 响应头 | 含 `Content-Security-Policy`、`Cache-Control: no-store`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer` |
| A12 | 页面源码(`curl -b jar.txt …/` 登录后) | `<script nonce="…">` 的 nonce 每次请求都不同 |

## D. 发布包

```bash
npm run build && npm run check:pack
npm pack
mkdir /tmp/vp-install && cd /tmp/vp-install && npm init -y
npm i /path/to/vault-panel-0.1.0.tgz
npx vault-panel --version        # 输出 0.1.0
npx vault-panel --no-open        # 能启动,页面样式和脚本正常
```

|---|---|

| D2 | 从安装包启动后,第 A、B 组的主要项目同样通过(重点:`web/index.html` 能被找到) |
